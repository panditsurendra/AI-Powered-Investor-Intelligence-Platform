📁 File-by-File Breakdown
1. Core Application Engine
main.py: The central entry point of the FastAPI application. It wires up all the routing endpoints, manages the application startup sequence (initializing the PostgreSQL database schema), and mounts the dashboard UI templates.
2. app/ - The API & Web Layer
routes/ingestion.py: Handles API requests to upload and process new PDF documents.
routes/chat.py: Powers the conversational interface, querying the Qdrant database to answer specific user questions about the uploaded reports.
routes/dashboard.py / health.py: Serves the dashboard UI data and provides a simple health check endpoint to verify the server is running.
(There are also static assets and HTML templates here to render the UI).
3. ingestion/ - The Document Processing Pipeline
ingest_documents.py: The orchestrator for the ingestion process. It ties together the extraction, chunking, and uploading processes.
pdf_to_markdown.py: Parses the raw unstructured PDF files and converts them into Markdown text, ensuring that tables and headers remain readable for the LLM.
semantic_chunker.py: Splits the long Markdown text into overlapping blocks/chunks so the context isn't lost but stays within the token limit of the embedding models.
qdrant_uploader.py: Takes the processed text chunks and uploads them directly into the Qdrant vector database.
4. vectorstore/ - Vector Database Management
create_index.py: A one-time setup script that creates the Qdrant collection (the vector database table) and defines its schema (dimensions, distance metric, and payload indexes for filtering).
qdrant_store.py: Contains the core logic for connecting to Qdrant, generating embeddings, uploading vector points, and running native similarity searches.
5. rag/ - Artificial Intelligence & Extraction
kpi_extractor.py: The heavy lifter of the AI pipeline. It takes a company name and year, queries the vector database for relevant text, and feeds it into the LLM. It uses a Pydantic schema (FinancialMetrics) to force the LLM to output clean, structured JSON containing the specific financial data rather than a conversational response.
6. database/ - Relational Storage (PostgreSQL)
postgres_sql.py: Connects to the PostgreSQL database container.
create_table.py: Defines the SQL schema structure for the financial KPI tables.
save_metrics.py: A utility file that takes the structured JSON generated by the LLM in kpi_extractor.py and inserts it safely into the SQL database.
metric.py: A retrieval utility to fetch the saved metrics from the database so they can be sent to the frontend dashboard.
7. Configuration & Environment Files
pyproject.toml & uv.lock: Managed by uv (a fast Python package manager), these define and lock all the necessary project dependencies (like FastAPI, LangChain, Qdrant Client).
.env / .env.example: Stores your secure environment variables, like your HUGGINGFACEHUB_API_TOKEN and local database connection URLs (e.g., QDRANT_URL).
